# prelabel.py 利用ガイド

学習済みモデルの検出結果をラベルの「下書き」として書き出すスクリプト。
矩形をゼロから描く代わりに、下書きを確認して直すだけにしてラベリングを速くする。

仕組みと設計判断は `PIPELINE.md` の「下書きラベル（prelabel.py）の考え方」を参照。

## 全体の流れ

```
動画 ──make_dataset.py──→ フレーム画像（enhanced）
                              │
                         prelabel.py ──→ 下書き .txt ＋ 確認リスト（prelabel_report.csv）
                              │
                    ラベリングツールで確認・修正（確認リストの上から）
                              │
                         label_qa.py で品質チェック ──→ train.py で学習
```

## 1. 環境を用意する

Docker も GPU も不要。Python と ultralytics（このフォーク）と学習済みの重みがあれば動く。

```bash
# リポジトリのルートで（初回だけ）
uv venv --python 3.11 .venv
uv pip install --python .venv/bin/python -e .
```

GPU PC で学習用の venv（`PIPELINE.md` の「実行環境」）がすでにあれば、それをそのまま使ってよい。
CUDA があれば自動で GPU を使う。

速度の目安（yolo26m・入力1280・1080p画像）:

| 環境 | 1枚あたり |
|---|---|
| Mac（CPU） | 約0.21秒（1,000枚で4分弱） |
| GPU PC | 未計測（CPU より大幅に速い想定） |

Mac の GPU（MPS）は使わない。ultralytics が自動で選ぶのは CUDA だけのため。

## 2. フレーム画像を書き出す

推論と同じ enhanced 表現で書き出す。ファイル名は `{動画名}_{6桁フレーム番号}.jpg` になり、
prelabel.py はこの名前から動画とフレーム番号を読み取る（名前を変えると対象外になる）。

```bash
cd shared
python make_dataset.py video1.mp4 video2.mp4 --mode enhanced --out datasets/frames
```

## 3. 下書きを作る

```bash
python prelabel.py datasets/frames --weights <学習済み.pt> --imgsz 1280
```

- `--imgsz` はモデルの学習解像度に合わせる（yolo26m-1280 なら 1280）
- `--out` を省略すると画像と同じフォルダに `.txt` を書く（labelImg 式）。
  **X-AnyLabeling で直すなら別フォルダにする**（`--out datasets/labels_draft`。理由は手順4）
- **既存の `.txt` は上書きしない。** 途中まで直したフォルダに掛け直しても、直したラベルは残る。
  作り直したいときだけ `--overwrite` を付ける
- 何も検出されなかったフレームには `.txt` を作らない
- 初回は出力先に `classes.txt`（`data.yaml` のクラス名一覧）も書く

終了時に次のような集計が出る。

```
画像 147枚: 書き出し 147 / 既存のため未変更 0 / 検出なし 0
キャップの下書きがあるフレーム: 16枚
内訳: {'detected': 485, 'duplicate': 5, 'overlap': 8, 'missing_cap': 6}
```

## 4. 確認リストを見ながら直す

ラベリングツールに下書きを読み込み、`prelabel_report.csv` の**上から順に**確認する。
確認すべきものほど上に並んでいる。

X-AnyLabeling は YOLO 形式の `.txt` を自動では読まない（自前の `.json` だけを読む）。インポートが必要。

**X-AnyLabeling を使うときは、下書きを画像と別のフォルダに書く**（例: `--out datasets/labels_draft`）。
X-AnyLabeling の YOLO インポートは画像フォルダ内の全ファイルを画像として扱うので、
`.txt` や `classes.txt` が画像と同じフォルダにあると、それを画像として開こうとしてエラーで止まる。

1. 画像フォルダを開く
2. 上部メニューの **Import**（または File → Import Annotations）で **YOLO**（矩形の検出）を選ぶ
3. 設定ファイルに `classes.txt` を指定する（prelabel.py が出力先に書いたもの）
4. 「Select Upload Folder」の欄には最初に画像フォルダの1つ上が入っているので、**Browse でラベルのフォルダを選び直して** OK

直した結果は画像の隣に `.json` で保存される。学習に回す前に **Export** で YOLO 形式に書き出す
（このときも `classes.txt` を指定する）。

| source | 意味 | 見るポイント |
|---|---|---|
| `missing_cap` | キャップのラベルが無いが、軌跡からは写っていそうなフレーム | **最優先。** 写っていれば矩形を足す。cx/cy に予測位置が入っている |
| `unfit` | 点が少なく軌跡を引けなかった区間の検出 | 本当にキャップか |
| `interpolated` | 取りこぼしたフレームに軌跡から補った矩形 | 位置と大きさのずれ |
| `outlier` | 軌跡から外れたので書かなかった検出 | 投げ始め・捕球付近は本物のことがある。本物なら矩形を足す |
| `duplicate` | 同じフレームの2個目以降のキャップ（書いていない） | 通常は確認不要 |
| `static` | 止まったままの誤検出（地面のキャップなど。書いていない） | 通常は確認不要 |
| `detected` | 書き出した検出。低信頼度（conf < 0.5）が先 | 低信頼度のものを中心に |
| `overlap` | キャップ以外のクラスの重複（書いていない） | 確認不要 |

`status` 列の意味:

- `written`: 今回書き出した
- `skipped_existing`: 既存の `.txt` があるので触っていない
- `not_written`: 除外したので書いていない
- `no_cap_label` / `existing_label_without_cap`: 付け忘れ候補（ラベルなし / 既存ラベルにキャップが無い）

## 5. 学習用データに回す

**確認していない下書きを学習に使わない。** モデル自身の誤りを再学習で固定してしまう。

以前の「ラベルの無い画像を捨てる」手順は使えない。人物クラスはほぼ全フレームに付くので、
キャップを見落としたフレームにも `.txt` ができる。そのまま学習すると
「ここにキャップは無い」と覚えてしまうため、`missing_cap` の行は必ず確認してから回す。

直し終えたら品質チェックを通す（`classes.txt` はラベルとして数えない）。

```bash
python label_qa.py datasets/train datasets/valid
```

## 調整できる値

距離はピクセル、フレーム数は**元動画のフレーム数**で数える
（`make_dataset.py --stride 3` で書き出した場合、画像3枚で9フレーム）。

| オプション | 既定値 | 意味 |
|---|---|---|
| `--conf` | 0.15 | 検出の信頼度閾値（track.py と同じ）。低めにして取りこぼしを減らし、誤検出は軌跡で落とす |
| `--inlier-px` | 20 | 軌跡からこれ以上ずれた検出は誤検出とみなす。投げ始めの本物が `outlier` になるなら上げる |
| `--segment-gap` | 15 | 検出がこれより長く途切れたら別の球とみなす |
| `--max-fill-gap` | 8 | これより長い欠損は補間しない（付け忘れ候補になる） |
| `--track-margin` | 3 | 軌跡の前後このフレーム数を付け忘れ候補の対象にする |
| `--static-extent-px` | 30 | 散らばりが縦横ともこれ未満の軌跡は止まった誤検出とみなす |
| `--other-conf` | 0.5 | キャップ以外のクラスの信頼度の足切り |
| `--batch` | 8 | 一度に推論する枚数 |
| `--data` | `data.yaml` | クラス名の対応に使う。モデルのクラスとは名前で対応付ける |

## うまくいかないとき

- **「名前が『動画名_6桁フレーム番号』でない画像」と出る**: ファイル名を変えていないか確認する。
  make_dataset.py が書き出した名前のまま使う
- **「モデルか data.yaml に cap クラスがありません」**: 重みのクラス名に `cap` が無い。`--data` と重みの組み合わせを確認する
- **「data.yaml に無いクラスは書き出しません」**: モデルにしか無いクラスは捨てている。必要なら `data.yaml` に足す
- **キャップの下書きがほとんど出ない**: `--imgsz` がモデルの学習解像度と合っているか、
  画像が enhanced 表現か（raw で書き出していないか）を確認する
