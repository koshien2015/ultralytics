# キャップ検出・コース推定パイプライン

キャップ（直径約4cm・球速約80km/h・モーションブラー大）を60fps動画から検出し、
投球ごとのコース・球速を推定するまでの一連の仕組みと、その設計判断の記録。

最終目的: 軌跡・球速・変化量・リリース位置の推定と、スコア記録（scorebook）への
コース自動入力。

## 全体構成

```
動画（原本・唯一の素材）
  │
  ├─ make_dataset.py ──→ 学習用フレーム画像（表現を選択: raw / enhanced / motion3ch）
  │                        └─ ラベリング（YOLO形式 .txt）──→ label_qa.py で品質チェック
  │                              └─ train.py で学習
  │
  └─ track.py（推論）
       ├─ tennis.py: モーション強調動画の生成（3フレーム差分）
       ├─ YOLO検出（強調フレームに対して実行）
       ├─ pitching_analysis.py: ストライクゾーン推定・リリース検出・正規化座標化
       └─ trajectory_fitter.py: 軌跡フィット後処理
            └─ {動画名}_analysis.json（コース・球速・補間済み軌跡）
```

## 各ファイルの役割

| ファイル | 役割 |
|---|---|
| `make_dataset.py` | 動画→学習用フレーム画像の書き出し（3表現対応） |
| `label_qa.py` | YOLOラベルの品質チェック（対応漏れ・サイズ異常・重複など） |
| `train.py` | 学習スクリプト（小物体向けデフォルト設定） |
| `tennis.py` | モーション強調前処理（3フレーム差分＋ガンマ補正） |
| `prefilter.py` | 推論フレームの事前絞り込み（投球区間の検出＋間引き） |
| `track.py` | 推論＋軌跡描画＋解析のエントリポイント |
| `pitching_analysis.py` | ストライクゾーン推定・リリース検出・座標正規化 |
| `trajectory_fitter.py` | RANSAC軌跡フィット・誤検出除去・欠損補間・コース/球速推定 |
| `tests/test_trajectory_fitter.py` | trajectory_fitter のユニットテスト（27件） |

## 実行環境（GPU搭載PCのローカル実行が前提）

学習・推論とも GPU 搭載 PC のローカルで実行する（Colab は使わない。
README.md の Colab ガイドは旧運用の記録）。

```bash
# 1. CUDA対応のPyTorchを先に入れる（バージョンは https://pytorch.org/ の指示に従う）
python -m venv .venv
source .venv/bin/activate          # Windowsは .venv\Scripts\activate
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121

# 2. このリポジトリ（ultralyticsフォーク）と依存を入れる
cd <リポジトリルート>
pip install -e .
pip install opencv-python pytest

# 3. GPUが認識されているか確認
python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```

ultralytics は CUDA を自動検出するので `train.py` / `track.py` に device 指定は不要。
複数GPUや明示指定が必要な場合のみ `model.train(device=0)` 等を追加する。

```bash
# テスト実行（GPU不要）
cd shared
python -m pytest tests/ -q
```

VRAM の目安: `imgsz=1280` の学習は yolov8m-p2 でバッチ4あたり 10GB 前後。
足りない場合は `--batch -1`（自動調整）か `--imgsz 960` に下げる。

※ Mac（開発機）でテストや小規模確認をする場合は `../pitching/.venv` が使える
（ultralytics 8.4.53 / numpy / pytest 導入済み。GPUなしなので学習には不向き）。

## 設計判断の記録

### 1. 解像度が最大のボトルネック（2026-07 判明）

ultralytics の `imgsz` デフォルトは 640。1080p 入力ではキャップ（画面上10px前後）が
縮小で3px程度になり検出限界を下回る。**学習・推論とも imgsz を上げるのが最優先の改善**。

- `train.py`: デフォルト `imgsz=1280`、モデルは P2ヘッド付き `yolov8m-p2.yaml`
  （stride=4 の高解像度特徴マップを持ち小物体に有効。通常構成は stride=8 が最小）
- `track.py`: `INFERENCE_IMGSZ = 1920` で推論

### 2. モーション強調入力は正当。ただし学習と推論で表現を一致させる

静止カメラ＋動体はほぼキャップのみ、という条件では3フレーム差分による
モーション強調（`tennis.py`）は有効（TrackNetが多フレーム入力で暗黙に学習する
動き情報を、単フレーム検出器に明示的に与えるのと同じ構図）。

**鉄則: 学習画像と推論入力は同じ表現で作ること。** ずれると分布不一致で精度が落ちる。
現行の推論入力は enhanced（元画像0.4＋差分0.6）なので、ラベリングも
`make_dataset.py --mode enhanced` の画像に対して行う。

既知の副作用:
- 静止クラス（打者・捕手・審判）はコントラストが0.6倍に落ちる。人物検出が
  不安定ならキャップ用と人物用で推論を分ける（人物は生フレーム）選択肢がある
- 投手の腕など「動くもの全部」が強調される → リリース付近の誤検出は
  軌跡フィット（下記4）が除去する分担

### 3. ラベルは表現から独立した資産

bbox座標はフレーム内位置なので、同一フレームから生成した raw / enhanced /
motion3ch のどの画像にも同じラベルが使える。`make_dataset.py` は表現によらず
`{動画名}_{フレーム番号:06d}.jpg` の同名で書き出すため、
**表現の切り替え実験は「画像再生成＋再学習1回」だけで済む**（ラベリング再作業なし）。

`motion3ch`（R=現フレームグレー, G=前差分, B=次差分）は外観と動きを混ぜずに
渡す実験用表現。enhanced で精度が頭打ちになったら試す。

### 4. 検出の穴は後処理（物理フィット）で埋める

最終出力に必要なのは「全フレームでの検出」ではなく「1球の軌跡」。
`trajectory_fitter.py` が投球単位で以下を行う:

- 時間の2次多項式 x(t), y(t) を RANSAC でフィット
- 軌跡に乗らない点＝誤検出を自動除去（そのため推論の conf は 0.15 と低めに設定し、
  取りこぼしを減らす側に振ってある）
- 欠損フレームをフィット曲線で補間
- 軌跡の最終時刻の位置からコース（9分割ゾーン）を判定
- 時間幅と投本間 9.22m から平均球速を算出

フレーム検出率が7割程度でも投球単位ではほぼ復元できる想定。

### 5. 座標系とゾーン番号の規約

`pitching_analysis.py` の正規化座標を全体で共有する:

- x: ストライクゾーン中心=0、ゾーン端=±0.5
- y: ゾーン下端=0、ゾーン上端=1
- t: リリースからの経過時間（秒）

9分割ゾーンは捕手（カメラ）視点で:

```
1 2 3   ← 上段（左・中・右）
4 5 6
7 8 9   ← 下段
```

ゾーン外は `"ball"`。境界ぴったりはストライク扱い。

### 6. 単眼カメラの限界（期待値）

- 奥行きが取れないため、横変化量（シュート/スライダー方向）の真値は保証できない
- 球速は「リリース〜捕球の時間幅で9.22mを移動した平均値」であり瞬間速度ではない
- 真の3D変化量が必要になったら2台目カメラ（同期60fps）を検討

### 7. 推論するフレームを前段で絞る（2026-08 追加）

キャップが写っているのは投球の 0.3〜0.5 秒だけで、90分の試合映像なら
全フレームの数%しかない。`prefilter.py` が2段階で推論対象を絞る。

1. **事前検出**: 3フレーム差分で投手ROIの活動量を測り、投球区間を出す。
   実測で実時間の約15倍速（720p/30fpsで450fps）なので、走査コストは無視できる
2. **間引き＋追従**: 区間内でも、未検出のうちは N フレームに1回だけ推論し、
   キャップを見つけたら連続推論に切り替えて飛翔を追い切る（既定 N=5、追従30フレーム）

効き方は素材で大きく変わる:

- **通常の試合映像**（投球間隔15〜20秒）→ 区間の絞り込みが効いて 1/5〜1/10
- **ハイライト編集**（投球が数秒おき）→ 区間がほぼ全編に広がるので絞り込みは効かない。
  間引きの分だけ（実測: test2.mp4 で 95.7% → 19%）

`track.py` の `ENABLE_PREFILTER = False` で従来の全フレーム推論に戻せる。

**残っている無駄**: `tennis.run()` が強調動画を全編分ディスクに書き出してから
推論に入る構造は手つかず。フレーム単位でオンザフライ生成すれば1パス分削れる
（cap-pitch-detector 側の `motion.enhance_frame` が同一手順の実装）。

## 標準ワークフロー

GPU PC 上（venv有効化済み）で:

```bash
cd shared

# 1. 動画から学習用フレームを書き出し（推論入力と同じ enhanced 表現で）
python make_dataset.py video1.mp4 video2.mp4 --mode enhanced --out datasets/frames

# 2. ラベリング（外部ツール）→ 品質チェック
python label_qa.py datasets/train datasets/valid

# 3. 学習（P2ヘッド + 1280px がデフォルト。VRAM不足なら --batch -1）
python train.py --data data.yaml --name cap_p2_1280

# 4. 推論＋解析（{動画名}_analysis.json にコース・球速が出力される）
python track.py test_video.mp4
```

5. カルマン予測ROIクロップ推論（実効解像度をさらに上げる場合）
