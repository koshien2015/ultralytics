# 時系列追跡・補完の検証レポート

**現在の状況: 実装と実動画への適用まで完了し、正解データとの比較は未測定です。** 人手の正解データが届くまで、精度の結論は出せません。この文書の数値はすべて実測値で、推測の数値は書いていません。

検証する問いは「AIモデルの精度が出ないとき、モデルを再学習せずに改善できるのか」です。モデル単体の検出精度と、時系列情報を使ったシステム全体の軌道推定精度を分けて評価します。

## 1. 研究背景

蓋は小さく高速で、モーションブラーも大きいため、YOLO はフレームごとに検出を取りこぼします。投球の解析に要るのは全フレームの検出ではなく、1球分の軌道です。そこで、前後のフレームの情報で検出抜けをどこまで補えるかを、再学習なしで検証します。

## 2. 検証仮説

| 仮説 | 内容 | 判定に使う指標 |
|---|---|---|
| H1 | YOLO単体で検出できないフレームの一部は、前後フレームの検出情報から補完できる | 補完したフレームのうち、正解から `match_radius_px` 以内に入った割合 |
| H2 | 時系列補完により、位置推定が可能なフレームの割合が向上する | カバー率と正しいカバー率の、YOLO単体との差 |
| H3 | 補完で検出抜けが減る一方、急激な軌道変化では位置推定誤差が増える可能性がある | `interpolated` と `predicted` の誤差、P95、誤対応、架空出力 |

YOLO単体の出力の71%は壁のロゴの周辺です（8章）。YOLO単体に対する改善には、欠損の補完ではなく候補の選び方の効果が多く含まれる見込みなので、比較は次の3段に分けます。

| 比較 | 分かること |
|---|---|
| Recall と YOLO単体のカバー率の差 | 正解の近くに候補はあるが、信頼度で選べなかった分。モデル単体の限界 |
| 最近傍追跡と YOLO単体の差 | 時系列を使った候補の選び方の効果 |
| 線形補間、カルマンフィルタ、RANSAC曲線と最近傍追跡の差 | 欠損の補完の効果。H1 と H2 はここで判定する |

## 3. 各手法のアルゴリズム

全手法が同じ `detections.json` を入力にするので、比較の間に再推論は行いません。

| 手法 | 処理 | 欠損の扱い |
|---|---|---|
| YOLO単体 | 各フレームで信頼度が最も高い候補を採る | 補完しない |
| 最近傍追跡 | 移動予測位置に最も近い候補を、最大移動距離の範囲で対応付ける | 追跡状態は保持するが、位置は出力しない |
| 線形補間 | 最近傍追跡の軌道で、前後の検出の間を時刻で線形補間する | 同じ軌道に挟まれた5フレームまでを補完する |
| カルマンフィルタ | 状態 `[x, y, vx, vy]` の等速運動モデル。マハラノビス距離で観測をゲートする | 5フレームまで予測を出力する |
| RANSAC曲線 | 最近傍追跡の軌道に、既存の `trajectory_fitter.py` で時間の2次式を当てる | 外れた検出を除き、曲線上で5フレームまで補完する |

RANSAC曲線は指示書の3手法に加えた比較対象です。既存の後処理より良いかを判断するために入れました。

実装上の共通の扱いは次のとおりです。

- 直近3回の観測で5px以上動いた点だけを出力します。壁のロゴのような静止物の誤検出を軌道にしないためです。
- 動いた点の直前の2点は遡って出力するので、最近傍追跡とカルマンフィルタも最大2観測分、先を見ています。
- 同じフレームに複数の軌道があるときは、実検出を優先し、次に動いた観測の多い軌道を採ります。軌道の良さは最後まで見て決めるので、この選択はオフラインの処理です。
- 最近傍追跡は、最大移動距離に加えて、移動予測位置から60pxを超える候補を対応付けません。欠損が続くと最大移動距離が広がり、別の物体に飛び移るためです。
- 差分強調は次のフレームを使うため、全手法が入力の時点で1フレーム先を見ています。先頭フレームは差分が0の暗い画像になります。
- 線形補間とRANSAC曲線は未来フレームを参照するオフライン処理です。
- 検出フレームの位置は全手法で YOLO の検出中心をそのまま出力します。

## 4. 使用データ・実験条件

| 動画 | 解像度 | fps | 推論フレーム数 | 位置づけ |
|---|---|---|---|---|
| `bXETW0GxBbkZoyHO.mp4` | 1280×720 | 30.0 | 5095 | 主評価 |
| `test_5.mp4` | 1920×1080 | 32.9 | 148 | 参考値（学習データに含まれる） |

差分強調は最終フレームを作らないので、どちらも総フレーム数より1少なくなります。

モデルは `yolo26m-1280px-120epoch.pt`、入力サイズは 1280、信頼度のしきい値は 0.15、前処理は差分強調です。`track.py` の前段フィルタは使わず、全フレームを推論しました。推論の環境は Mac の CPU で、1フレームの処理時間の中央値は `bXETW` が 312.2ms、`test_5` が 310.1ms でした。

差分強調にかかった時間は未計測です。

しきい値はすべて `temporal_experiment/experiment.yaml` にあります。`max_prediction_error_px=60` と `motion_window=3` は、`bXETW` の全フレームの検出結果を見て決めました。正解データは使っていませんが、評価区間の検出を見ています。今後の調整は調整用の区間だけで行います。

正解データは GPU PC の人手ラベルを使う予定です。`datasets/prelabel_trial/labels` は `prelabel.py` が出力した下書きなので、正解には使いません。

## 5. 評価指標の定義

定義は `temporal_experiment/README.md` の「評価指標」のとおりです。位置を出力しなかったフレームを除いて精度が良く見えることを防ぐため、誤差は「出力フレームのみ」と「全フレーム」の両方を出します。全フレームの誤差では、欠損フレームに `error_cap_px` を与えます。

## 8. 失敗したケース

正解データなしで確認できた現象は次の3つです。

**固定物への誤検出。** `bXETW` では、壁の白いロゴ（座標はおよそ (1087, 323)）の周辺15px以内に、674フレームで候補が出ました。YOLO単体の出力864件のうち613件（71%）がこのロゴの周辺です。元動画の切り出しで、ロゴであることを目視で確認しました。信頼度だけで候補を選ぶ YOLO単体では、この誤検出を避けられません。この613件はロゴ周辺の位置で数えた値で、蓋がその場所を通ったフレームを含む可能性があります。

追跡の初期実装もこのロゴに軌道を乗っ取られ、最近傍追跡の検出108件がロゴの周辺に載りました。線形補間は蓋とロゴの間に最大393pxの直線を引き、RANSAC曲線は蓋の点を外れ値として捨てました。静止物の判定と予測位置からの距離の制限を入れた後は、ロゴ周辺の出力は最近傍追跡、線形補間、RANSAC曲線で0件、カルマンフィルタで1件です。線形補間で挟んだ2点の距離の最大は63pxになりました。

**軌道の末尾の予測。** `bXETW` のカルマンフィルタの予測265件のうち、220件（83%）は軌道の最後の検出より後の出力です。検出の間を埋めた予測は45件でした。末尾の予測は後の観測で裏付けられないので、架空軌道の候補です。評価区間を投球の終わりより長く取り、架空出力を確認します。

**採用されなかった検出。** YOLO単体の検出864フレームのうち636フレームは、どの軌道にも採用されていません。ロゴ以外の誤検出か、見逃した本物かは正解データで確かめます。軌道は47本で、1本あたりのフレーム数の中央値は4、最大は13です。

## 9. 結果から言えること・言えないこと

言えることは次のとおりです。

- 同じ検出結果に5手法を適用し、検出と推定を区別して出力できます。
- `bXETW` では、候補の選び方を信頼度から軌道の整合性に変えるだけで、ロゴ周辺の出力を613件から0〜1件に減らせました。これは再学習なしで変えられる部分です。ただし、減った出力に本物の蓋が含まれるかは未確認です。
- 補完の出力は、架空の軌道を作らない条件のもとで動きます。先頭、末尾の線形補間、上限を超える欠損、別の軌道の間は補完しません。これは合成データのテストで確認した動作です。

言えないことは次のとおりです。

- H1、H2、H3 の判定は、まだ言えません。
- 線形補間を第一候補にしたのは、目視の印象と手法の単純さによる判断です。線形補間とRANSAC曲線のどちらの位置が正しいかは、まだ言えません。
- 追跡や補完によって精度が上がったかどうかは、まだ言えません。件数が増えても、正しい位置が増えたとは限りません。
- 検証する動画は2本で、`test_5` は学習データに含まれます。撮影条件の一般化はできません。

## 10. 今後の改善案

- 正解データでの評価の後、失敗条件に応じて等加速度モデルや、カルマンスムーザーのような前後を使う推定を比較します。
- 実運用では、カルマン予測の位置を中心に切り出して推論すれば、見逃しの再検出につながる可能性があります。
- TrackNet のような多フレーム入力のモデルは今回の範囲外で、将来の比較対象です。
